📌 PROBLEM STATEMENT

Post-Quantum Cryptography in DNSSEC: Signature Size Bloat & Latency

⚠️
Signature Inflation: ML-DSA-44 signatures expand to 2,420 bytes vs classical ECDSA (64B) — a 38× size bloat.
⚠️
Packet Fragmentation: Exceeds DNS standard 1,232-byte UDP buffer, triggering expensive TCP fallbacks and amplification risks.
⚠️
Resolver Congestion: Drastically increases cache footprint, memory overhead, and verification latency.
💡 OUR SOLUTION

RootOps: Merkle Tree Ladder (MTL) PQC-DNSSEC Testbed

Standard-compliant zone condensation combining Merkle Tree Ladder Mode (IETF CFRG draft) with ML-DSA-44 (Alg 201).

⚡
92% Signature Size Reduction Only 1 root signature per zone. RRSIGs carry compact ~190B ladder paths fitting inside 1,232B UDP MTU.
🌐
5-Tier Delegation Chain Isolated Docker hierarchy: Root (.) → TLD (test.) → SLD (aiori3.test.), PowerDNS Recursor 5.3, and PQC client.
🔄
Dynamic Zone Evolution Resolvers validate records across updates using cached ladders without re-signing the entire zone.
📊
Empirical Benchmark Suite Live measurements of crypto latency, UDP/TCP query sizes, ladder endurance, and PQC chain validation.
